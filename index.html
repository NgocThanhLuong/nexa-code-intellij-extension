06 · Governance & security

Autonomy with a control plane.

NexaCode does not trust a model response as authority. Runtime decisions are re-derived from platform state, identity, tool metadata and policy before anything touches the workspace.

The invariant

The model proposes. The platform decides. The developer approves.

Read operations can flow quickly. Writes, shell commands, Git mutations and risky extensions stop at explicit governance boundaries.

01 / IDENTITY

Multi-tenant RBAC

Tenant, project, user and role scope follow requests through runs, tools, approvals and audit records.

02 / FILESYSTEM

Workspace containment

Relative-path validation, real-path checks, symlink containment and protected-path rules limit local access.

03 / EXECUTION

Bounded operations

Timeouts, output caps, allowlists, concurrency controls and workspace locks constrain runtime work.

04 / ACCOUNTABILITY

Approval + audit

Risky actions create real approval state. Every tool execution records structured, redactable audit context.

05 / NETWORK

SSRF-aware web tools

Public HTTP/HTTPS only, with credentials, localhost, private ranges, redirects and response sizes controlled.

06 / RECOVERY

Checkpoint + rollback

Git-backed or snapshot checkpoints make approved multi-file operations reviewable and recoverable.

09 · Common questions

Clear boundaries by design.

NexaCode Studio is in active development. Exact capabilities remain deployment-aware and are surfaced to the IntelliJ client at runtime.

Does my code stay on my machine?

Filesystem, terminal, Git, test and IDE operations execute locally when an IntelliJ session is attached. Relevant code context and structured tool observations may still be sent through the control plane to the model endpoint you configure, subject to your deployment and provider policy.

Can NexaCode use a local model?

Yes. The model gateway uses the OpenAI-compatible protocol, so a locally hosted endpoint such as Ollama can be used. Compatible remote endpoints can be configured through the same platform boundary.

Can the model bypass approval by marking a tool safe?

No. Approval is derived again by the Java platform from the registered tool, identity, project and real execution state. It is not trusted from model output or sidecar metadata.

Why is the ReAct loop in Java?

Java owns orchestration so tool policy, approval, audit, retrieval, budgets and durable state stay in one control plane. The LangGraph sidecar is currently a stateless model-and-tool-schema caller behind a replaceable adapter.

Is it tied to one framework or provider?

No. Framework and provider clients sit behind platform-owned interfaces. Model calls intentionally use one OpenAI-compatible contract rather than provider-specific logic leaking into the core.

Is NexaCode Studio publicly released?

The platform is under active development. This website documents the current product direction and implemented architecture; packaging and broader release details will be announced here as they become available.
